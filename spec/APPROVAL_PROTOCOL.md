# Approval Protocol

## 1. Purpose

Some actions require approval before they can be executed. An approval is a single-use record that a specific human or service principal has approved a specific action.

## 2. Approval Record

An approval record contains:

- `approval_id` — unique identifier.
- `action_id` — the action being approved (or a hash of the proposed action).
- `approver_id` — the principal approving the action.
- `authorization_id` — the authorization under which the approval is granted.
- `policy_version` — the policy version.
- `approved_at` — approval timestamp.
- `expires_at` — expiry timestamp (approvals expire if not used quickly).
- `used` — whether the approval has been used (default false).
- `used_at` — when the approval was used (null if unused).
- `signature` — cryptographic signature by the approver.

## 3. Approval Operations

### 3.1 Request

An approval request is generated by the authorization engine when an action requires approval. The request includes the proposed action, the authorization, and the policy version.

### 3.2 Issue

An approval is issued by:

1. The approver reviews the request.
2. The approver signs the approval.
3. The approval is recorded as a signed event in the ledger.

### 3.3 Verify

An approval is verified by:

1. The approval record exists in the ledger.
2. The approval is in an active state (not revoked, not expired, not used).
3. The approval's action matches the proposed action.
4. The approver is authorized.
5. The signature is valid.

### 3.4 Use

An approval is used by:

1. The agent executes the approved action.
2. The approval's `used` flag is set to true.
3. The `used_at` timestamp is recorded.
4. The approval cannot be reused.

### 3.5 Revoke

An approval may be revoked by the approver before use. Revocation is a new signed event.

## 4. Dual Approval

Some actions require dual approval (two approvers). Dual approval records contain two approval signatures. Dual approval is required for:

- Production deployments of high-impact systems.
- Privilege changes for high-privilege agents.
- Cross-organization delegations involving critical infrastructure.
- Destructive actions on sealed resources.
- Cryptographic key destruction.

## 5. Approver Authorization

Approvers are authorized by policy. The policy specifies:

- Which principals may approve which action classes.
- Whether dual approval is required.
- Whether regulator notification is required.
- Whether the approval must be sealed (e.g., for judicial authorizations).

## 6. Invariants

- Approvals are single-use.
- Approval reuse is rejected.
- An expired approval cannot be used.
- A revoked approval cannot be used.
- Dual approval requires two distinct approvers.
- Approver signatures are verified.
